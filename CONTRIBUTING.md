# Contributing

We welcome architecture criticism, independent reproductions, counterexamples, documentation improvements and clearly labeled extensions. Keep the original goal in view: an integrated, vendor-neutral proposal for end-to-end AI governance and safety.

Use an issue to identify the affected domain, acceptance gate or requirement and explain the practical consequence. For experiments, include the protocol and source revision, archive hash, environment, exact command, raw observations, independent protected-resource state and evidence comparison. Report `not_executed`, timeouts and incomplete attempts explicitly.

Preserve original evidence. Put new output in a new directory. Do not replace an adverse finding with a success label because a fixture expected the adverse behavior. Separate authorization, substantive correctness, effect enforcement, evidence integrity and remedy.

For proposed changes, distinguish a correction to the existing protocol from a new scenario. Explain changed assumptions, test oracles and dependencies. A narrower successful test does not erase a wider failure. No contribution should claim measured human judgment, legitimacy, jurisdictional compliance or production performance without a corresponding study.

Never submit API keys, access tokens, private keys, customer data or private cloud logs. Use synthetic examples. See SECURITY.md for sensitive reports.

Software licensing and contributor permissions remain unresolved; see LICENSE_STATUS.md. Until those terms are finalized, use discussion issues rather than submitting substantive code for incorporation. There is no contributor license agreement or implied patent license in this repository.
